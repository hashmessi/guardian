# Phase 8 Plan 02: Deterministic Isolated Demo Reset & Modeled Avoided Scrap Engine

## Goal
Implement the isolated demo reset mechanism (`DEMO-02`) that creates a new isolated demo run (`run_id` / session checkpoint) while strictly preserving all previous audit records in SQLite for immutable audit trail integrity. Implement the configurable modeled avoided scrap calculation (Step 10 of Demo Story) with explicit assumptions and defect avoidance volume logic.

## Requirements Addressed
- `DEMO-01`: Economic interpretation of prevented scrap value (Step 10 of Demo Story).
- `DEMO-02`: One-click scenario reset for deterministic replay (isolated run, audit preserved).
- `DEMO-03`: Prototype disclosures and assumption transparency.

## Proposed Files
- `src/process_guardian/storage/repository.py`: Add session isolation / run identifier support and demo reset query methods that preserve historical audit logs while resetting active telemetry and orchestrator states.
- `src/process_guardian/api/routes/demo.py`: REST endpoint `POST /api/demo/reset` and `GET /api/demo/economic-impact` supporting configurable scrap costs (default ₹450), returning avoided defective cycles and modeled avoided scrap value with explicit assumptions.
- `src/process_guardian/api/schemas/demo.py`: Pydantic request and response schemas for demo reset and economic evaluation.
- `src/process_guardian/api/app.py`: Register demo router and wire dependencies.
- `tests/test_demo_reset_and_economics.py`: Unit and integration tests for isolated reset, audit preservation, and economic calculations.
