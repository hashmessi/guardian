### Implementation Details
- **Orchestrator Lifecycle Steps:**
  1. Ingest telemetry cycle.
  2. Evaluate drift (EWMA/CUSUM). If drift alert and state is `MONITORING`, transition to `DRIFT_DETECTED`.
  3. Predict quality risk ($P_{\text{risk}}$) & check epistemic uncertainty. If risk > threshold, transition to `EVALUATING_INTERVENTIONS`.
  4. Generate and optimize candidate interventions. If valid minimum-cost action found, propose recommendation and transition to `INTERVENTION_RECOMMENDED`.
  5. Apply intervention (operator simulated/logged). Transition to `INTERVENTION_APPLIED`.
  6. Transition to `COOLING_WINDOW` and monitor cycles.
  7. Once cooling window completes, run `RecoveryVerifier.evaluate_recovery()`.
     - If approved: transition to `RECOVERY_VERIFIED`, compute containment report via `ContainmentEngine`, transition back to `MONITORING`.
     - If rejected: transition to `INTERVENTION_FAILED` / re-evaluate or escalate.
- **Verification Criteria:**
  - Full end-to-end benchmark test passes without mock dependencies.
  - Zero state machine violations.
  - Correct isolation of suspect parts and zero uncontained scrap.
