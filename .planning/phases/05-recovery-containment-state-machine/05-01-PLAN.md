# Phase 5 Plan 01: Explicit System State Machine Engine

## Goal
Implement the explicit 13-state system state machine (`STMC-01`) directly in code (`STMC-02`), governing the complete intervention lifecycle with deterministic transition guards, context tracking, and an auditable transition history.

## Requirements Addressed
- `STMC-01`: System implements explicit state machine:
  `HEALTHY → DRIFT_SUSPECTED → DRIFT_CONFIRMED → QUALITY_RISK_HIGH → DIAGNOSING → INTERVENTION_EVALUATION → (ABSTAIN | QC_REQUIRED | RECOMMEND) → APPLIED → RECOVERY_CHECK → (FAILED → REASSESS | VERIFIED → RELEASE) → INTERVENTION_MEMORY`.
- `STMC-02`: State machine exists explicitly in code, not hidden inside UI logic.

## Proposed Files
- `src/process_guardian/state_machine/schemas.py`: `ProcessState` enum (13 states), `StateTransitionRecord`, `MachineContext`.
- `src/process_guardian/state_machine/engine.py`: `ProcessStateMachine` evaluating transitions based on incoming cycle signals, risk, and recovery outcomes.
- `src/process_guardian/state_machine/__init__.py`: Public package exports.
- `tests/test_state_machine.py`: Unit tests validating all valid transitions, invalid transition rejections, context persistence, and state history recording.

## Verification
