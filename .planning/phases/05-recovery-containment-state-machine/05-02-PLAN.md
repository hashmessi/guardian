# Phase 5 Plan 02: Post-Intervention Recovery Verifier

## Goal
Implement the **Post-Intervention Recovery Verifier** (`RECV-01..05`) that confirms parameter movement in the expected direction, recalculates drift and defect risk dynamically from live post-intervention telemetry, enforces a stability window ($N \ge 3$ consecutive cycles), verifies Quality Contract release conditions, and emits a structured recovery evaluation report.

## Requirements Addressed
- `RECV-01`: After intervention, system confirms parameter movement in expected direction.
- `RECV-02`: System re-evaluates drift and recomputes quality risk post-intervention.
- `RECV-03`: System checks stability window (not immediate release — verifies sustained recovery).
- `RECV-04`: System verifies Quality Contract conditions before releasing production.
- `RECV-05`: System produces recovery status output: risk before/after, stability before/after, recovery status (VERIFIED/FAILED), release decision.

## Proposed Files
- `src/process_guardian/recovery/schemas.py`: Data models for recovery status, release decision, and evaluation report.
- `src/process_guardian/recovery/verifier.py`: `RecoveryVerifier` tracking post-action stability window, parameter movement, contract verification, and timeout handling.
- `src/process_guardian/recovery/__init__.py`: Public package exports.
- `tests/test_recovery_verifier.py`: Unit tests validating parameter movement confirmation, dynamic risk recomputation, stability window enforcement, quality contract verification, and structured report outputs.
