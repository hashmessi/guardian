# Plan 07-02: Screen 1 (Live Process) + Screen 2 (Incident Diagnosis)

## Objective

Build Screens 1 and 2. Screen 1 delivers the DETECT experience: instrument gauge bars with
operating envelope shading, process state timeline, and quality contract panel. Screen 2 delivers
DIAGNOSE: risk escalation trajectory, drift evidence panel, affected cycle window, and ranked
root-cause contributors with honest epistemic language.

### Task 1: Build SignalGauge component (reusable, used on Screen 1)

<action>
Create frontend/src/components/SignalGauge.jsx:

Props: label (string), value (number), unit (string), min (number), max (number),
envelopeMin (number), envelopeMax (number), isDrifting (bool)

Renders horizontal instrument gauge bar:
  - Track: full-width, 10px height, border-radius:4px, background:var(--color-mist)
  - Envelope zone: absolute positioned shaded region inside track showing fingerprint normal range
    background:var(--color-lilac), opacity:0.6
  - Current value marker: 3px wide vertical bar, absolute positioned at (value-min)/(max-min)*100%
    color: isDrifting ? var(--color-wine) : var(--color-charcoal)
  - Value label: right-aligned, 16px weight:540, num class
  - Unit label: 12px stone gray
  - Drift indicator: if isDrifting show "DEVIATION" in wine pill, else "NORMAL" in lagoon pill

Calculate marker position: clamp((value - min) / (max - min) * 100, 0, 100)%

NO animations on the marker -- position is the state, no pulse/glow.
</action>

### Task 7: Build Screen 2 -- IncidentDiagnosis.jsx + IncidentDiagnosis.css

<action>
Replace frontend/src/screens/IncidentDiagnosis.jsx with full implementation.

LAYOUT: Two-column CSS grid (7fr / 5fr).

Left column (7fr):
  "RISK ESCALATION" card:
    Two large numbers side by side: "3%" (stone, fw:600, 28px) -> arrow -> "72%" (wine, fw:600, 28px)
    Below: Lead Time label + value from riskData.lead_cycles or driftData.lead_cycle_count (e.g. "12 cycles")
    Confidence: "Confidence" label + riskData.confidence_score formatted as percentage

  "DRIFT EVIDENCE" card (label-section header: "DRIFT EVIDENCE"):
    Table of detection methods that fired. Data from driftData.
    Columns: Method | Status | Severity
    Methods: EWMA, CUSUM, Multivariate Distance (Mahalanobis), Slope/Trend
    Show "FIRED" pill (wine) if method contributed, "--" if not.
    Severity: numeric from driftData.severity_score or per-method scores if available.

  "AFFECTED CYCLE WINDOW" card:
    Horizontal bar showing: [last_known_good] ... [drift_detection] ... [current_cycle]
    Labels below bar at each marker. Values from containmentData or driftData.
    If no containment data: show "Window: Cycles {drift_start} to {current_cycle}" as text.

Right column (5fr):
  "ROOT CAUSE CONTRIBUTORS" section (label-section header):
    List of RootCauseBar components from riskData.root_cause or interventionData.root_cause_contributors
    Each bar: label=signal name, percentage=contribution pct, rank=position, evidenceText=evidence string
    Honest language check: evidenceText must come from API, never fabricated.
    If no root cause data: "Insufficient data for root cause analysis" in stone gray 14px.

  "CONFIDENCE" card:
    Circular arc gauge -- SVG arc (NOT a gradient ring, hairline stroke only).
    Center number: confidence percentage (fw:600, 24px, charcoal)
    Arc: 120-degree sweep, stroke:var(--color-violet) for filled portion, stroke:var(--color-mist) for remainder
    Below: "Model Confidence" label in stone gray 12px

usePolling endpoints:
  /api/quality/risk (2000ms) -> riskData (includes root_cause, confidence_score, risk_state)
  /api/process/drift (2000ms) -> driftData (is_drifting, contributing_signals, severity_score, lead_cycle_count)
  /api/interventions/recommendation (2000ms) -> interventionData (for root_cause_contributors if not in riskData)
  /api/containment/window (2000ms) -> containmentData (last_known_good_cycle, suspect_window_start, suspect_window_end)

Screen panel: id="panel-diagnosis" role="tabpanel" aria-labelledby="tab-diagnosis"

CRITICAL: All evidence strings rendered on this screen MUST come from API data.
If a field is null/empty, render nothing or "Insufficient data for this signal" in stone gray.
Never write hardcoded evidence text like "Variance increased 3.2sigma" -- that must come from API.
</action>
