# Plan 07-03: Screen 3 (Intervention + Recovery) + Audit Trail Drawer

## Objective

Build Screen 3 and the Audit Trail drawer. Screen 3 delivers the INTERVENE+VERIFY act:
candidate comparison table, 7-field recommendation card, the single Apply Intervention button
(the only Midnight Wine filled action in the entire UI), recovery verification panel, and
scrap containment summary. The audit drawer gives judges the full 10-event evidence chain.

State: isOpen (bool, default false)

underline on hover (0.2s ease), shows "?" when closed and "?" when open.

When isOpen=true: drawer slides up from bottom, height ~40vh, overflow-y:auto.
Background: white, border-top: hairline, padding:24px.

Inside drawer:
  "AUDIT TRAIL -- EVIDENCE CHAIN" label-section header
  
  Vertical timeline: left-side 2px hairline, events right of line
  
  Fetch from /api/containment/window (already polled) + construct audit chain.
  
  10 chain events in order (render what data is available, skip if null):
    1. SIGNAL CHANGE -- type pill: violet, timestamp, description from driftData
    2. DRIFT EVIDENCE -- type pill: violet, detection methods that fired
    3. RISK ESTIMATE -- type pill: wine, quality risk percentage + confidence
    4. CAUSE EVIDENCE -- type pill: violet, top root cause contributor
    5. CANDIDATE ACTIONS -- type pill: mist, count of candidates evaluated
    6. SELECTED ACTION -- type pill: wine, recommended action name
    7. EXPECTED OUTCOME -- type pill: mist, expected risk reduction
    8. OBSERVED OUTCOME -- type pill: lagoon if positive, wine if negative
    9. RECOVERY DECISION -- type pill: lagoon (VERIFIED) or wine (FAILED)
    10. PRODUCTION DISPOSITION -- type pill: lagoon, quarantine window summary

  Each event row:
    Left: timeline dot (8px circle, colored by pill type) on the vertical line
    Right: event type pill + timestamp + description text (14px charcoal)
    If data for that event is unavailable: render row with "--" description in stone gray

  Bottom of drawer: "Export Audit Log" ghost button
    background:transparent, border:1px solid var(--color-mist), color:var(--color-charcoal)
    border-radius:8px, padding:8px 16px, 14px
    onClick: downloads audit data as JSON (JSON.stringify of all available audit chain data)

The drawer must always be rendered in DOM (for CSS transition), with isOpen controlling visibility.

### Task 8: Build Screen 3 -- InterventionRecovery.jsx + InterventionRecovery.css

<action>
Replace frontend/src/screens/InterventionRecovery.jsx with full implementation.

LAYOUT: Three zones stacked vertically.

Zone A -- "CANDIDATE ACTIONS" label + CandidateTable:
  Data from usePolling('/api/interventions/recommendation', 2000)
  Pass candidates array to CandidateTable
  isAbstain: recommendationData.operator_mode === 'ABSTAIN' or confidence < threshold

Zone B -- "RECOMMENDATION" label + RecommendationCard:
  Data from same recommendationData
  onApply: async function that calls applyIntervention(), sets applying/applied state
  Show apply button; on success set applied=true and trigger recovery polling

Zone C -- RecoveryPanel:
  usePolling('/api/recovery/status', 2000) -> recoveryData
  usePolling('/api/containment/window', 2000) -> containmentData
  Only renders when intervention has been applied (applied===true or recoveryData has data)

Bottom -- AuditDrawer:
  Always mounted; trigger slides it up from bottom of viewport

usePolling endpoints:
  /api/interventions/recommendation (2000ms) -> recommendationData
  /api/recovery/status (2000ms) -> recoveryData
  /api/containment/window (2000ms) -> containmentData

State:
  isApplying: bool -- button loading state
  applied: bool -- shows recovery panel after apply
  applyError: string|null -- error message under button

Screen panel: id="panel-intervention" role="tabpanel" aria-labelledby="tab-intervention"
