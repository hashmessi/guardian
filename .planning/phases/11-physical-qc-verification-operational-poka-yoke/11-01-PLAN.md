# Plan 11-01: Mandatory QC Checkpoint State Machine & CTQ Evaluation Engine (QCHK-01)

## Objective
Implement `MANDATORY_QC_CHECKPOINT` in the finite state machine and the physical CTQ measurement evaluator in `src/process_guardian/quality/` and `src/process_guardian/state_machine/`. Enforce the operational poka-yoke invariant: production release is strictly blocked post-stabilization until a physical CTQ measurement (part weight in grams within tolerance, visual blemish inspection pass-fail, inspector ID) is recorded.

## Scope
- State Machine:
  - Add `ProcessState.MANDATORY_QC_CHECKPOINT = "MANDATORY_QC_CHECKPOINT"` in `schemas.py`.
  - Update `VALID_TRANSITIONS` in `engine.py` to support `RECOVERY_CHECK -> MANDATORY_QC_CHECKPOINT -> (RELEASE | DIAGNOSING)`.
- Physical QC Engine:
  - Create `src/process_guardian/quality/qc_checkpoint.py` with:
    - `PhysicalCTQMeasurement`: part weight (nominal 220.0g +/- 1.5g), sink_mark (< 0.10mm), flash (bool), burn_mark (bool), short_shot (bool), inspector_id, timestamp.
    - `QCCheckpointResult`: is_passed, failure_reasons, ctq_details.
    - `QCCheckpointVerifier`: evaluates measurement against strict automotive CTQ criteria and stores active QC verification status.
- State Machine Guard:
  - Add guard rule refusing transition to `RELEASE` if `MANDATORY_QC_CHECKPOINT` has not passed.
- Unit Tests: `tests/test_qc_checkpoint.py`
  - Test passing CTQ measurement authorizes release.
  - Test out-of-tolerance part weight (e.g. 216.2g) rejects release and flags fail reason.
  - Test visual flash/sink mark rejects release.
  - Test state machine poka-yoke transition protection.
