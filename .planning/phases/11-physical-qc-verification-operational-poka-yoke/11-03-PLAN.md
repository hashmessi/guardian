# Plan 11-03: Physical Scrap Containment Boundary Card, REST API & End-to-End Verification (CNTN-05, QCHK-01, QCHK-02)

## Objective
Expose the physical QC checkpoint and operational checkpoints via REST API endpoints, integrate physical scrap containment boundary milestones into the containment engine, create the UI components (`ContainmentBoundaryCard.jsx`, `QCCheckpointModal.jsx`, `OperationalCheckpointsCard.jsx`), and execute full end-to-end verification.

## Scope
- Containment Engine:
  - Enhance `src/process_guardian/containment/engine.py` to record `stabilization_cycle` and `qc_passed_cycle`, tracking all 7 cycle milestones: Last Good, Drift Start, Suspect Lot, Action Applied, Stabilized, QC Passed, Release.
- REST API: `src/process_guardian/api/routes/qc.py`
  - `POST /api/qc/submit`: Submit physical CTQ measurement (part weight, visual check, inspector ID).
  - `GET /api/qc/status`: Get current mandatory QC checkpoint status.
  - `GET /api/checkpoints/operational`: Get evaluation of the 3 PS02 operational checkpoints.
  - `POST /api/checkpoints/spray`: Record mold-release spray application.
  - `GET /api/containment/boundary`: Return the complete 7-milestone physical scrap containment boundary payload.
  - Register route in `src/process_guardian/api/app.py`.
- Frontend UI:
  - Create `frontend/src/components/ContainmentBoundaryCard.jsx` and `.css` displaying the physical cycle milestone track.
  - Create `frontend/src/components/QCCheckpointModal.jsx` and `.css` for physical CTQ measurement recording.
  - Create `frontend/src/components/OperationalCheckpointsCard.jsx` and `.css` for the 3 PS02 shop-floor gates.
  - Integrate into `IncidentDiagnosis.jsx`, `InterventionRecovery.jsx`, and `AppShell.jsx`.
- Testing:
  - Create `tests/test_qc_api.py`.
  - Run full test suite (`pytest tests/`) ensuring 100% green pass.
  - Run frontend production build (`npm run build`).
