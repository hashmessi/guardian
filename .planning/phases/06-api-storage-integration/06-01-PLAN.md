# Phase 6 Plan 01: SQLite Database Engine & 17-Table Schema Layer

## Goal
Implement the comprehensive SQLite database persistence layer (`STOR-01`) and unified event model (`STOR-02`), providing typed schemas, connection management, table initialization, and high-performance repository CRUD operations for all 17 plant and operational entities.

## Requirements Addressed
- `STOR-01`: SQLite database with 17 tables:
  `machines`, `molds`, `parts`, `recipes`, `materials`, `cycles`, `process_fingerprints`, `quality_contracts`, `drift_events`, `quality_predictions`, `intervention_candidates`, `intervention_recommendations`, `intervention_applications`, `recovery_events`, `containment_windows`, `checkpoints`, `audit_log`.
- `STOR-02`: Event model uses consistent event object schema (`event_id`, `machine_id`, `mold_id`, `part_id`, `recipe_id`, `cycle_id`, `timestamp`, `event_type`, `severity`, `signals`, `quality_risk`, `confidence`).

## Proposed Files
- `src/process_guardian/storage/schemas.py`: Pydantic models for the 17 tables, unified `GuardianEvent` schema, and DTOs.
- `src/process_guardian/storage/database.py`: Database connection manager, schema initialization DDL for all 17 tables, foreign key enablement, and transaction helpers.
- `src/process_guardian/storage/repository.py`: `GuardianRepository` class providing typed insertion, querying, and audit logging for all entities.
- `src/process_guardian/storage/__init__.py`: Package exports.
- `tests/test_storage.py`: Unit tests validating table creation, CRUD operations across all 17 tables, event serialization, and transaction rollbacks.
